## v0.9.1 - 2026-08-26
### Fixed
* A Cloud Run service whose Terraform bootstrap writes the traffic split and the tag as two separate blocks — `traffic { percent = 100 }` next to `traffic { tag = "blue" }`, both following the latest revision — is no longer refused. Both entries resolve to one revision and Cloud Run serves them as a single tagged entry at 100%, which is why the console shows blue carrying everything while the tool read the spec block, found the percentage on an entry with no tag, and asked for the bootstrap that was already there. The tag is now read off the entry beside it when the two aim at the same revision, and the first release pins the pair back to the one-line form the tool writes. It stays a refusal when both tags claim the serving revision, since then there is no side to deploy away from, and when the tag is pinned to a revision while the percentage follows whatever is newest — a rule and a reference are not the same target even when they happen to agree today.

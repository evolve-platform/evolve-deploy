## v0.11.2 - 2026-08-28
### Fixed
* `container` is accepted on every target type whose driver reads it — cloud-run, cloud-run-job, container-app and container-app-job alongside ecs — instead of being refused as ECS-only. The Cloud Run driver has picked its container from that field since 0.11.0, but the config layer rejected the file before a driver ever saw it, and Cloud Run is the one platform that cannot fall back: its containers have no conventional name the way a Container App has `main`, so `PickContainer` refuses to guess and a service running a sidecar was undeployable from either side. It stays refused on lambda, function-app and helm, where nothing reads it.

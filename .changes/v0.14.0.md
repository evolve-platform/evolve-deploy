## v0.14.0 - 2026-10-08
### Changed
* `uses: job` is renamed after each cloud's own resource: `container-app-job` on Azure, `cloud-run-job` on GCP and `ecs-task` on AWS — the same names as the target types, because a deploy file already speaks its cloud's language and a neutral name bought a portability no deploy file has. A file still using `job` is refused before anything is read, with the names there are; replace it with the one for your cloud and nothing else changes. The name for another cloud is refused while planning, with the one this cloud uses — `cloud-run-job is gcp's; on azure this is uses: container-app-job`. `base` and `target` are now options of `ecs-task` alone, so the schema refuses them on the other two, where a job is a resource of its own and needs neither.

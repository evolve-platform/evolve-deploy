## v0.18.0 - 2026-11-12
### Changed
* `apply --only` on a blue-green release also stages every blue-green service it leaves out, at the version that service serves now, so a release always leaves the environment on one side instead of splitting it. A following service never causes a release on its own, and one whose serving version cannot be told is refused with the `--set` that settles it. A service staged at a version that did not move — following, or named at the version it already serves — skips its `before` and `after` hooks; a hook that must run whenever its service is staged sets `when: always` (`when: changed` is the default). The plan shows both.

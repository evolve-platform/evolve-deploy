## v0.13.0 - 2026-10-08
### Added
* A hook can run a job: `uses: job` with the job's `name` starts one run of a Container Apps job on Azure, a Cloud Run job on GCP or a one-off ECS task on AWS, on the version being released, and waits for it to finish — so a migration goes in `before` and gates the release like any other hook, and a permissions load goes in `after`. The image is written onto the job first, because a migration has to run against what is about to go out rather than what is serving, and neither Cloud Run nor ECS can give a run an image any other way. A `command` runs that command line instead of the job's own for that one run; on Azure and GCP the job gets Terraform's command back afterwards whether the run worked or not, so the next run without one does not run the last one's. On AWS, where there is no job resource, the job is what `before_deploy` was in ecs-deplojo — a task definition family, registered per run from Terraform's `<name>-base` like an ecs target, and a RunTask — except that it waits and judges the run by the container's exit code, and starts the task in the cluster and network of the service's own ecs target, without which a Fargate task does not start; `target` names another, and `base` another family. A `timeout` stops a run that takes longer and fails the hook — stopped rather than walked away from, because a migration still running under a release that went ahead is what it is for; on AWS, where ECS keeps no task timeout, it is the only one there is. The job is Terraform's and is never created here: one that does not exist is refused while planning, with nothing written. Like every hook it prints nothing when it succeeds; a failed run names itself and says where its logs are.
* The config file has a JSON Schema, and the tool checks every file against it before reading it. A mistake is now reported under the path of the key it is about, with the line it is on, alongside every other mistake in the file — where the decoder used to stop at the first value it could not place and name a Go type (`cannot unmarshal !!str into []string`, `field comand not found in type config.Target`). A misspelt key or value says what it was probably meant to be, and a key that belongs elsewhere says why: `does not apply when type is lambda`. Each release publishes the schema at `https://deploy.evolve-platform.com/schema/v<version>.json` and as `latest.json`, so an editor pointed at it with a `# yaml-language-server: $schema=` line checks the file while it is typed, against the same rules; `evolve-deploy schema` prints the one built into the binary. `keep_warm` now takes `true` or `false` only, where the YAML decoder also took `yes` and `on`.
